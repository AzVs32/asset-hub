# 正式 crate 开发规范

适用于 `crates/` 及其所有子目录，补充根目录 `AGENTS.md`，不重复通用协作规则。

## 1. 依赖与职责

- 保持依赖方向清晰，禁止循环依赖；核心抽象不反向依赖具体实现或应用入口。
- 新增、移除或移动 crate 时，同步检查 workspace 成员、依赖路径和已有文档；按用途区分普通、测试和条件依赖。
- 按职责组织模块，避免无必要的分层、重复转发和面向假设需求的抽象。

## 2. 接口与类型

- 公共接口明确输入约束、返回结果、错误和副作用；接口变化同步调用方及测试。
- 承载业务约束的类型在构造、解析、转换和反序列化时使用一致的校验；不暴露绕过校验的可变入口，派生接口和构造器同样维护不变量。
- 后端及平台差异封装在实现边界内，不支持的行为明确拒绝，不降低接口承诺或公开不可用的占位实现。

## 3. 数据、资源与错误

- 组件只管理自己拥有的数据和结构；涉及配置或持久化格式变化时，明确兼容、迁移及失败处理，保留已有数据。
- 明确资源所有权、释放责任及异步操作的取消和失败语义；阻塞操作放到适当的执行环境，大数据按需分块处理。
- 在适配边界转换错误并保留原始原因；对外错误及诊断输出不得泄露凭据等敏感信息。

## 4. 验证

- 回归测试覆盖真实行为、边界和失败场景；同一接口的多个实现复用契约测试，测试基于公开接口。
- 涉及非默认 feature、条件编译或平台差异时，验证受影响的构建组合，并说明未验证的环境。
- 按变更范围选择单个 package 或整个 workspace，在所属 workspace 执行检查；常用检查如下，单包检查可使用 `-p <package>`：

```sh
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all --check
```
