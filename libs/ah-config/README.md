# ah-config

[简体中文](README.zh.md)

Typed TOML configuration with isolated spaces, validated snapshots and a derive macro for application-owned configuration types.

## Usage

Add the dependencies to your `Cargo.toml`:

```toml
[dependencies]
ah-config = "0.2.0"
```

### Quick start

Create `config/config.toml` in your application's package directory:

```toml
[http]
port = 9000
```

Declare, load and read the configuration in `src/main.rs`:

```rust
use ah_config::Registry;

#[derive(ah_config::Config)]
#[config(key = "http", deny_unknown_fields)]
struct HttpConfig {
    #[config(default = 8080)]
    port: u16,
}

fn main() -> Result<(), ah_config::ConfigError> {
    let config = Registry::for_space("default")?
        .load_optional("config/config.toml")?;
    for warning in config.warnings() {
        eprintln!("warning: {warning}");
    }
    let http = config.get::<HttpConfig>()?;
    println!("HTTP port: {}", http.port);
    Ok(())
}
```

Run with `cargo run`; this prints `HTTP port: 9000`. If the file is missing,
loading uses the declared defaults and the application prints a warning; an omitted
`port` uses `8080`. An invalid value such as `port = "wrong"` is an
error and never falls back to the default. Loading returns only after all selected
sections have passed decoding and validation. Relative file paths use the package
directory during Cargo runs, or the executable's directory when launched directly;
use `with_base_dir(absolute_directory)` to choose a base explicitly.

### Inspecting registered configuration

```rust
for section in ah_config::Registry::declarations() {
    println!("{}: {} in {:?}", section.key(), section.type_name(), section.spaces());
}
println!("Available spaces: {:?}", ah_config::Registry::spaces());

let registry = ah_config::Registry::for_space("default")?;
for section in registry.sections() {
    println!("Selected: {}", section.key());
}
```

`Registry::spaces()` returns sorted, deduplicated linked space names.
`Registry::declarations()` returns all linked sections sorted by full key, Rust
type name and space memberships, retaining conflicts for diagnosis. These global
queries do not read files or run default factories and validators; they also work
when selecting a space would fail. A registry's `sections()` lists its selected
declarations; the loaded snapshot retains that list through `sections()`.
Only crates linked into the current program appear. Type names are diagnostic
labels, not persistent identifiers. `UnknownSpace` includes the available names
in its printed output and `available_spaces()` getter.

### Missing files and warnings

Use `load_optional(path)` to load an existing file or automatically use declared
defaults when the read reports `NotFound`. Defaults still undergo validation;
missing required fields without defaults remain errors. A successful fallback
records `ConfigWarning::MissingFile { path }` with the resolved absolute path.
Read it through `LoadedConfig::warnings()` and emit it through your application's
logger, as in the quick start. The library does not print warnings itself.
An existing empty file produces no missing-file warning, and an old snapshot
retains its warning even if the file is created later.

`load_required(path)` remains available when an absent file must be an error.
Neither loader falls back on permission, syntax, type or validation failures.

### Choosing declarations and defaults

| Declaration | Ownership and access |
| --- | --- |
| `Config` with `key = "http"` | Independent root section; read with `get::<HttpConfig>()` |
| `Config` with `parent = VfsConfig, key = "wasm"` | Independent child section; read separately without adding a parent field |
| `ConfigValue` | A field owned by another configuration type; read through that field |

`get::<T>()` requires the public `ConfigSection` trait generated by `Config`.
Ordinary types and `ConfigValue` types fail to compile. A valid section outside
the selected space returns `NotRegistered`, with its key and snapshot location.
Generic helpers can use `T: ah_config::ConfigSection`; `T::KEY` is its full TOML
path. Parent relationships and space membership are independent: a child neither
inherits its parent's spaces nor automatically selects it for loading.

| Default declaration | Missing-input behavior |
| --- | --- |
| Field `#[config(default = expression)]` | Supply this field's value when absent |
| Field `#[config(default)]` | Use the field type's `Default` when absent |
| `Option<T>` field | Become `None` when absent and no inherited default exists |
| Struct `#[config(default)]` | Generate `Default` from declared field defaults and use it as section defaults |
| Type `#[config(default = factory())]` | Generate `Default` using the factory and use it as section defaults |
| Ordinary `#[derive(Default)]` or manual `Default` | Construct Rust values; not automatically used as section loading defaults |
| Direct `Default::default()` call | Construct without running configuration validation |

A default on a nested type does not fill an absent owning field by itself; mark
that field with `#[config(default)]` to opt in. For `ConfigValue`, type-level
defaults generate `Default` for the owning field to use; they do not register a
section. Do not also derive or implement `Default` when a type-level
`#[config(default...)]` already generates it. Detailed merge rules follow below.

### Declaration options

| Feature | Provides |
| --- | --- |
| `derive` (default) | `#[derive(ah_config::Config)]` and `#[derive(ah_config::ConfigValue)]` |

Set `default-features = false` to use the loading API without the macro. `Registry`, `LoadedConfig`, `ConfigSection`, `SectionInfo`, `ConfigWarning`, `ConfigError` and `ConfigErrorKind` are always available.

`Config` declares a section and requires a key. `ConfigValue` declares a nested struct or enum without registering a section. Both generate Serde `Serialize` and `Deserialize`; do not derive those traits again. Standard derives such as `Clone` and `Debug` remain your choice.

| `#[config(...)]` option | Declared behavior |
| --- | --- |
| `key = "http"` | Required single TOML path segment; use `parent` for child sections |
| `parent = VfsConfig` | Register beneath the parent type, with extension permission checked at compile time |
| `spaces = ["default", "plugins"]` | Space membership; defaults to only `default` when omitted |
| `default = expression` | Type: generate `Default`; field: supply a missing value. Functions use `default = factory()` |
| `default` | Field: use `Default`; struct: generate `Default` from field declarations |
| `default = Self::Variant` | On an enum: select a default variant and generate `Default` from its field declarations |
| `validate = check` | Section validator accepting `&T` and returning `Result<(), E>` |
| `tag = "backend"` | Selector field for an enum with payloads; unsupported on structs |
| `rename = "name"` | External name of one field or variant |
| `deny_unknown_fields` | Opt into strict field checking |

Fields and enum variants always use `snake_case`: `LocalFile` becomes `local_file`. Use a single-item `rename` for standard symbols such as `MiB` or other special names. Explicit section keys, tag names and string values are used as supplied.

Both `Config` and `ConfigValue` generate `Default` for every type-level `default` declaration. Bare `default` on a struct constructs it from field defaults; `default = expression` returns the expression, including a function call. An enum-level `default = Self::Variant` constructs the selected variant from its field defaults. Automatic field construction requires explicit defaults or `Option<T>`. Do not also implement or derive `Default` when a type-level default is declared; put custom construction logic in a factory instead. Factories must not call the generated `Default` recursively.

`Config` uses that generated implementation as its section's loading defaults. Without a type-level declaration, a manual or derived `Default` is allowed but does not automatically become loading defaults. A nested type implementing `Default` does not by itself default an absent parent field; opt in with `#[config(default)]` or supply an explicit default expression. Direct `Default::default()` calls construct values without running configuration validation.

Missing fields use available inherited or field defaults; `Option<T>` becomes `None`, and fields without an available default remain required. Merely implementing `Default` for a field type does not make that field optional. A partially supplied nested struct uses its field defaults rather than implicitly invoking its type's `Default`; inherited parent defaults still merge recursively.

A struct section without a type default can be built from field defaults and optional fields. Missing required fields still fail. Struct type defaults merge recursively with file fields; arrays and explicitly supplied enum values are replaced at any nesting depth. An omitted enum retains its inherited default. A supplied enum must include its selector and required fields; its own field defaults still apply, even when selecting the same variant. An explicit invalid value never falls back to a default. Only one `default` declaration is allowed at each location. Function calls use normal Rust expression syntax with parentheses; bare function names are not invoked implicitly. Validator errors must convert to `Box<dyn Error + Send + Sync>`.

Select a space with `Registry::for_space(name)`, load a TOML file with `load_required(path)` or `load_optional(path)`, then read a shared `Arc<T>` with `get::<T>()`. Explicit spaces replace the default membership; space names do not prefix TOML paths. All selected configurations must load and pass validation before a snapshot is returned.

Pass a relative file path such as `"config/config.toml"` directly to either loading method. Cargo runs and tests automatically use the package directory, including Release runs. When the program is launched directly without Cargo's runtime environment, relative paths start at the executable's directory. Both are independent of the working directory. Absolute file paths are used unchanged. For a custom location, call `with_base_dir(absolute_directory)` before loading; it overrides the automatic base. Relative or empty bases fail when loading a relative file path. Paths stored inside configuration values are not rewritten.

An optional file may be missing; other loading failures are still errors. Each load produces an independent snapshot. File changes do not update existing values; load again to obtain new values. Default merging, validation and error handling are covered in the examples below.

Use `ConfigError::kind()` to classify a failure and `path()`, `section()`,
`field_path()` and `space()` to locate it. `Display` and `Debug` include available
location metadata without printing configuration values or underlying causes.
For example, a bad HTTP port can print:

```text
configuration section has an invalid type or field [file: "/app/config/config.toml"] [section: "http"] [field: "http.port"] [space: "default"]
```

`field_path()` includes the full key and array indices when decoding provides
them, such as `service.http.limits.0.memory_limit_mb`. Location methods return
`Option`: preparation failures have no file path, syntax errors may have no
section, and section validators do not identify a specific field. Original
parser, I/O and validation errors remain accessible through `Error::source()`;
explicitly displaying that chain may expose input values or custom messages.
A non-table ancestor is `Deserialize`, rather than `MissingSection`.

### Independent child sections

A module can add `vfs.wasm` without changing the original `VfsConfig`. Declare
its parent type explicitly; the parent may be exported by another crate:

```rust
#[derive(ah_config::Config)]
#[config(key = "vfs")]
pub struct VfsConfig {
    enabled: bool,
}

#[derive(ah_config::Config)]
#[config(parent = VfsConfig, key = "wasm")]
pub struct WasmConfig {
    memory_limit_mb: u64,
}
```

```toml
[vfs]
enabled = true

[vfs.wasm]
memory_limit_mb = 128
```

After loading the same space, read `get::<VfsConfig>()` and
`get::<WasmConfig>()` independently. A sibling can declare
`parent = VfsConfig, key = "rpc"`; further descendants name their immediate
parent type. The original Rust struct has no `wasm` or `rpc` field.

Only named structs derived with `Config` and without `deny_unknown_fields`
allow external children. A strict parent, a `ConfigValue` parent, an enum parent,
or a child key matching an existing parent field (including a renamed field)
fails to compile. Each key must be one nonempty ASCII segment containing letters,
digits, underscores or hyphens. Bare dotted keys such as `key = "vfs.wasm"` are
rejected; migrate them to explicit parent declarations so extension checks cannot
be bypassed. Exact duplicate registered paths still fail with `KeyConflict`
when selecting a space, including duplicates declared in different crates.

A child can itself become a parent through another explicit `parent` declaration.
Depth does not enable strict checking: only an explicit `deny_unknown_fields`
closes a named section to further children.

Each section retains its own defaults and validator. Space selection remains
independent: omitted `spaces` still means only `default`; a child neither inherits
its parent's spaces nor automatically loads its parent. Put both declarations
in the same space when they should load together. Extensible parents ignore
unknown fields, including unregistered child tables; extension permission does
not validate arbitrary TOML keys during compilation.

`ConfigValue` serves a different purpose: when `VfsConfig` explicitly contains a
`wasm: WasmConfig` field, derive `ConfigValue` on the nested type and retrieve it
through that field. It is not independently registered, and calling
`get::<WasmConfig>()` fails to compile. The same field cannot also be an external
child section.

### Examples

Read the examples in the order below. Each addresses one configuration task and includes its run command. Read each Rust file alongside the TOML files with the same filename prefix.

The first four examples incorporate validation into their configuration declarations and include invalid fixtures exercised by their tests: conversion errors reject invalid types, while validators check the assembled values, including defaults.

| Example | Demonstrates |
| --- | --- |
| [Basic](examples/basic.rs) | The declare → select → load → get flow, required and optional fields, nested values with `Config` and `ConfigValue`, and section validation |
| [Defaults](examples/defaults.rs) | Value expressions, function calls and `Default`, nested values and partial overrides, with invalid values rejected rather than replaced |
| [Database](examples/database.rs) | Enum selectors, variant-specific required fields, enum-level defaults and validation of the selected variant |
| [Spaces](examples/spaces.rs) | Private and shared declarations in independently selected spaces, with validation limited to selected declarations |
| [Extensions](examples/extensions.rs) | Independent `vfs.rpc` and `vfs.wasm` sections, owned nested values and child validation |
| [Snapshots](examples/snapshots.rs) | Retain old shared values while explicitly loading a new snapshot |

## Maintenance

The commands below run from the ah-config source root, the directory containing this README and `Cargo.toml`.

- `src/` contains the public API; `macros/src/` implements the derive macro.
- `examples/` contains usage and behavior tests; `tests/loading.rs` and `tests/spaces.rs` cover loading rules, missing-file warnings and space isolation, `tests/discovery.rs` checks side-effect-free declaration queries and selected metadata, `tests/errors.rs` checks error context and causes, `tests/defaults.rs` covers default rules, `tests/nested_defaults.rs` checks nested enum replacement, `tests/naming.rs` checks naming and explicit overrides, `tests/extensions.rs` checks parent/child defaults, descendants and space isolation, `tests/paths.rs` checks file resolution and working-directory independence, and `tests/runtime.rs` checks loading without declarations.
- `tests/fixtures/` contains a standalone consumer project for integration checks.

### API documentation

The [API reference](https://docs.rs/ah-config/latest/ah_config/) describes generated implementations, attribute locations and type restrictions. To build it locally:

```sh
cargo doc --all-features --no-deps
```

The generated documentation is at `target/doc/ah_config/index.html`; open it in a browser. If `CARGO_TARGET_DIR` is set, the page is under `doc/ah_config/index.html` in that directory.

### Checks

Install Python 3.12+ and Rust with `rustfmt` and `clippy`, then run the unified checks from the full repository checkout:

```sh
python3 ci/check.py
```

The entry point checks tests and examples, feature combinations, formatting, Clippy and documentation. It also runs the renamed-dependency consumer and external-crate registration in Debug and Release/LTO, verifies expected compilation failures (including conflicting defaults, duplicate `Default` implementations and invalid parent/child declarations), and builds the actual `.crate` archives after unpacking them. The unpacked runtime uses the unpacked macro package through a temporary local patch. Nothing is published.

Checks stop on failure with a nonzero exit status. The full log is saved at `target/ci-logs/native.log`; `CARGO_NET_OFFLINE=true` can be set when dependencies are already cached. Execution and logging reuse the repository's `.github/checks` support, as in ah-id; this command does not require changing CI workflows.

An independent source copy can still use Cargo directly, for example `cargo test --workspace --all-features --locked`. Ordinary `cargo test` does not run the independent consumer checks or archive verification.
